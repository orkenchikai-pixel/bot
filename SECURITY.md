# Безопасность

Документ для владельца сервиса и технического специалиста: от чего защищён бот, где это в коде, что сделать перед запуском и как действовать при инциденте.

## Модель угроз

| Угроза | Защита | Где в коде |
|---|---|---|
| Поддельные «сообщения пациентов» на вебхук | Подпись HMAC-SHA256 (`X-Hub-Signature-256`) с App Secret, сравнение за постоянное время; без секрета вебхук не работает. Повторы отсекаются по `wamid`. Номер отправителя — только цифры | `src/whatsapp/webhook.ts`, `src/server.ts` |
| Спам, флуд, атака множеством номеров, накрутка расходов на ИИ | Лимиты на номер (в минуту/час/сутки) с автоблокировкой, отсев одинаковых сообщений, лимит новых чатов на клинику, лимит ответов ИИ одному чату в час/сутки, дневной бюджет на клинику и на весь сервис, ограничение одновременных запросов к Claude, обрезка длинных сообщений | `src/security/spam.ts`, `src/messaging/dispatcher.ts` |
| Prompt injection и джейлбрейк («забудь правила», поддельный SYSTEM, инструкция в имени профиля) | Служебный контекст — только в сообщениях с ролью `system`, которые пациент не может подделать. Правила в промпте: текст пациента — не указание. Удаляются невидимые символы (ASCII smuggling, Trojan Source) | `src/agent/prompt.ts`, `src/security/sanitize.ts` |
| ИИ «уговорили» сделать лишнее | Инструменты работают только с записями номера, с которого пишут; все аргументы проверяются на сервере (формат, рабочие часы, занятость, сроки, лимиты); лимит изменений записей в сутки | `src/agent/tools.ts` |
| Утечка промпта, фишинг, чужие ссылки и телефоны в ответе | Фильтр ответов: канареечная метка, дословные строки инструкций, запросы данных карты/CVV/SMS-кодов, ссылки только на домены клиники, чужие номера скрываются, служебные id вырезаются. Срабатывание — тревога администратору и запись в аудит | `src/security/output-guard.ts` |
| Доступ к чужим данным | ИИ не получает номера телефонов и данные других пациентов. Админ-API: токен клиники видит только свою клинику | `src/agent/prompt.ts`, `src/admin/routes.ts` |
| Подбор токена админки | Токены от 32 символов, в файлах клиник — только SHA-256, сравнение за постоянное время, блокировка IP после 10 неудачных попыток за 15 минут, журнал аудита всех действий | `src/admin/routes.ts` |
| Утечка файла базы или бэкапа | Шифрование AES-256-GCM: тексты переписки, история для ИИ, имена, комментарии. Ключ — вне базы (`DATA_ENCRYPTION_KEY`), подмена данных обнаруживается | `src/security/crypto.ts`, `src/db/repo.ts` |
| Персональные данные в логах | Номера маскируются (`7701*****67`), тексты сообщений и аргументы инструментов в логи не пишутся (кроме режима отладки) | `src/security/pii.ts` |
| Кража токена WhatsApp через подменённый URL вложения (SSRF) | Токен отправляется только на домены Meta, без редиректов, с лимитом размера файла | `src/whatsapp/client.ts` |
| XSS и кликджекинг в веб-симуляторе | Экранирование, строгий CSP с nonce, `X-Frame-Options: DENY`, ключ в `#фрагменте` и заголовке (не в URL и логах); в production симулятор только с ключом. Ключ симулятора (`SIMULATOR_KEY`) отдельный от токена админки: ссылку на тестовый чат можно дать клинике, доступа к данным пациентов она не даёт | `src/server.ts`, `src/simulator/` |
| Огромные запросы (исчерпание памяти) | Лимиты тела запроса: вебхук 1 МБ, админка 64 КБ, симулятор 16 КБ; Caddy — 2 МБ | `src/server.ts`, `Caddyfile` |
| Уязвимые зависимости | `package-lock.json`, `npm audit` в CI, Dependabot | `.github/` |
| Компрометация процесса | Docker: не root, файловая система только для чтения, без capabilities, `no-new-privileges`, лимиты памяти и процессов; наружу открыт только Caddy | `Dockerfile`, `docker-compose.yml` |
| Утечка ключей при установке, порча настроек | Мастер: ключи вводятся скрыто и на экран не выводятся; в запросах к API они передаются через временный конфиг curl, а не аргументы команды (их не видно в списке процессов); `.env` с правами 600; секреты из `openssl rand`; ключ шифрования базы не перегенерируется при повторном запуске; ответы проверяются строго (домен не может внедрить настройки в Caddyfile); правка файла клиники и смена ключей применяются только после проверки, иначе — возврат прежней версии | `install.sh`, `scripts/dental-bot.sh` |
| Уязвимости в базовом образе и Caddy | `dental-bot update` пересобирает образ со свежим `node:22-slim` и обновляет Caddy; перед этим делает резервную копию базы, а если новая версия не прошла проверку или не запустилась — возвращает прежнюю | `scripts/dental-bot.sh` |
| Сообщения после сбоя доставки | Сообщения старше 12 часов ИИ не обрабатывает — их получает администратор | `src/messaging/dispatcher.ts` |

## Как проверяется

- **191 автотест** (`npm test`): модульные, интеграционные (HTTP, вебхук, админ-API), сценарии атак, гонка за слот, property-based/fuzz-тесты (fast-check генерирует сотни случайных входов), проверка исходников на невидимые символы, прогон мастера установки (с вопросами и без, ошибки ввода, неверные ключи, повторный запуск, откат неудачной правки).
- **Покрытие кода**: `npm run test:coverage` (отчёт в `coverage/`).
- **Red-team живой модели**: `npm run redteam` — 15 атак (вытаскивание промпта, поддельный SYSTEM, чужие данные, отмена чужой записи, фишинг, джейлбрейк, назначение лекарств, неотложное состояние, подмена цены, просьбы не по теме и др.) с автоматическими проверками и отчётом `data/redteam-report.md`. Запускайте перед каждым релизом и после смены промпта или модели.
- **CI** (GitHub Actions): типы, тесты с покрытием, `npm audit`, shellcheck, настоящая установка мастером в Docker с проверкой HTTPS, подписи вебхука, закрытого админ-API, резервной копии, обновления и повторного запуска.

## Чек-лист перед запуском

Сервер:
- [ ] Ubuntu LTS с автоматическими обновлениями безопасности (`unattended-upgrades`).
- [ ] Вход по SSH только по ключу, пароли и вход root отключены.
- [ ] Файрвол: открыты только 22, 80, 443 (`ufw allow OpenSSH && ufw allow 80,443/tcp && ufw enable`).
- [ ] Сервер в стране, где этого требует закон о персональных данных (см. COMPLIANCE.md).
- [ ] Шифрование диска у хостинга, если доступно.

Секреты:
- [ ] Все секреты сгенерированы мастером установки или `npm run token`, `.env` с правами `chmod 600`, в git не попадает.
- [ ] `DATA_ENCRYPTION_KEY` сохранён в менеджере паролей (без него база не читается).
- [ ] Для каждой клиники — свой токен администратора (`admin.token_sha256`), суперадмин-токен только у владельца. Клинике для проверки бота давайте ссылку с `SIMULATOR_KEY` (`dental-bot info`), а не токен админки.
- [ ] В Anthropic Console — отдельный workspace и месячный лимит расходов.
- [ ] Meta Business Manager: двухфакторная аутентификация у всех администраторов; токен системного пользователя только с правами `whatsapp_business_messaging` и `whatsapp_business_management`.

Запуск:
- [ ] `NODE_ENV=production` (в docker-compose уже стоит) — сервер не стартует без обязательных секретов.
- [ ] HTTPS через Caddy (`DOMAIN` в `.env`).
- [ ] Внешний мониторинг доступности `https://домен/health` (UptimeRobot и аналоги).
- [ ] Резервные копии `data/backups` регулярно копируются на другой сервер или в хранилище.
- [ ] `npm run redteam` пройден без замечаний.

## Регулярно

- Раз в неделю — `dental-bot update` на серверах, PR от Dependabot и `npm audit`.
- Раз в месяц — журнал аудита (`GET /admin/audit`) и тревоги фильтра безопасности.
- Раз в квартал — проверочное восстановление из резервной копии и смена токенов администраторов.
- После любых изменений промпта или модели — `npm run redteam`.

## Если случился инцидент

| Что произошло | Что сделать |
|---|---|
| Утёк `ANTHROPIC_API_KEY` | Удалить ключ в Anthropic Console, создать новый, проверить расходы |
| Утёк токен WhatsApp или App Secret | Отозвать токен системного пользователя / сбросить App Secret в Meta, обновить `.env`, перезапустить |
| Утёк токен администратора | Сгенерировать новый (`npm run token`), заменить `ADMIN_TOKEN` или `token_sha256` клиники, проверить журнал аудита |
| Тревога «фильтр остановил ответ ИИ» | Посмотреть переписку, при необходимости заблокировать номер (`POST /admin/blocklist/...`), добавить сценарий в `scripts/redteam.ts` |
| Подозрение на утечку базы | Сохранить логи, сменить все секреты, оценить состав данных (зашифрованные поля без ключа не читаются), уведомить клинику-оператора; клиника уведомляет регулятора и пациентов в сроки, установленные законом |

Сообщить об уязвимости: напишите владельцу сервиса напрямую, не публикуя детали до исправления.

## Остаточные риски

- Счётчики антиспама живут в памяти и обнуляются при перезапуске (блокировки сохраняются в базе). Для нескольких экземпляров сервера нужен Redis.
- Ключ шифрования хранится на том же сервере: шифрование защищает от утечки файла базы и бэкапов, но не от полного захвата сервера.
- ИИ может ошибиться в формулировке. Цены, слоты и записи берутся только из данных и проверяются кодом, но клинике стоит периодически просматривать переписку.
