# Персональные данные и закон: чек-лист

> Это не юридическая консультация. Документ описывает, что умеет система, и вопросы, которые нужно закрыть с юристом до продажи клиникам. Требования зависят от страны клиники.

## Кто есть кто

| Роль | Кто | Что это значит |
|---|---|---|
| Оператор персональных данных | Клиника | Решает, зачем обрабатываются данные пациентов, отвечает перед пациентами и регулятором |
| Обработчик (по поручению оператора) | Вы — владелец сервиса | Обрабатываете данные от имени клиники по договору, обеспечиваете меры защиты |
| Субобработчики | Meta (WhatsApp Cloud API), Anthropic (ИИ), хостинг, Telegram (уведомления) | Получают часть данных для работы сервиса — их нужно перечислить в договоре и в политике клиники |

## Что система делает сама

| Требование | Как реализовано |
|---|---|
| Согласие на обработку (в т.ч. сведений о здоровье) | Режим `explicit` (по умолчанию): до согласия сообщения пациента **не передаются ИИ** и хранятся только у вас. Кнопки «Согласен/Не согласен», версия согласия, журнал решений (`consent_log`) — доказательство для проверок. Новая версия политики — согласие спрашивается заново |
| Информирование | В запросе согласия: кто оператор, какие данные, кому передаются (Meta, Anthropic), ссылка на политику, как отказаться и отозвать |
| Сообщение, что отвечает ИИ | В первом сообщении и при вопросе «вы бот?». Опция `ai_label_each_message` — значок 🤖 в каждом ответе |
| Отказ и отзыв согласия | Отказ — кнопкой или «нет»; отзыв — в любой момент словами («отзываю согласие»). После этого ИИ не обрабатывает сообщения, их получает администратор |
| Отписка от рассылок | «СТОП» / «СТАРТ» работают всегда, без ИИ; напоминания таким пациентам не отправляются |
| Минимизация данных | Номер телефона не передаётся ИИ; фото не сохраняются; в логах номера маскируются, тексты не пишутся |
| Сроки хранения | Переписка удаляется через 180 дней, записи обезличиваются через 3 года, журнал аудита — 3 года (настраивается) |
| Право на доступ и удаление | Пациент просит в чате → задача администратору (`privacy_requests`). Выгрузка: `GET /admin/patients/:clinic/:phone/export`, удаление: `DELETE /admin/patients/:clinic/:phone?confirm=…` |
| Меры защиты | Шифрование полей базы, разграничение доступа по клиникам, журнал аудита, HTTPS, резервные копии — подробно в SECURITY.md |
| Локализация | База — на вашем сервере; разместите его в стране клиник |

## Что нужно сделать вам (владельцу сервиса)

1. **Договор с каждой клиникой** (поручение на обработку персональных данных / DPA): предмет и цели, перечень данных, меры защиты (из таблицы выше), список субобработчиков, уведомление клиники об инцидентах, удаление данных по окончании договора, ваша ответственность.
2. **Сервер в нужной стране.** Требования хранить базы с персональными данными граждан внутри страны есть, например, в Казахстане (Закон РК «О персональных данных и их защите», ст. 12), России (152-ФЗ, ч. 5 ст. 18), Узбекистане (Закон «О персональных данных», ст. 27-1). Выбирайте местный хостинг.
3. **Трансграничная передача.** Переписка уходит в Meta и Anthropic за рубежом. Обычно это требует согласия пациента (оно включено в текст запроса согласия) и упоминания в политике клиники. Проверьте с юристом требования вашей страны к таким передачам.
4. **Условия поставщиков.** Anthropic по коммерческим условиям не обучает модели на данных API и удаляет их в течение 30 дней (кроме случаев нарушения правил использования). Meta хранит сообщения Cloud API до 30 дней. Для WhatsApp действуют правила для бизнеса: с 15 января 2026 года запрещены боты «общего назначения» — бот обязан отвечать только по теме клиники (это заложено в промпт и проверяется `npm run redteam`); писать первым можно только шаблонами и только тем, кто не отписался.
5. **Закон об ИИ.** В Казахстане действует Закон «Об искусственном интеллекте» (№ 230-VIII от 17.11.2025, в силе с 18.01.2026) с требованиями прозрачности: пользователь должен понимать, что общается с ИИ. Бот сообщает об этом сам; при необходимости включите маркировку каждого сообщения (`ai_label_each_message`). Уточните у юриста требования к маркировке для вашего случая.
6. **Внутренние документы**: политика информационной безопасности, порядок реагирования на инциденты (см. SECURITY.md), ответственный за защиту данных.

## Что нужно сделать клинике

1. Опубликовать политику обработки персональных данных и указать ссылку в `privacy.policy_url` (а юрлицо — в `privacy.operator_name`). Мастер установки спрашивает и то и другое; если политики ещё нет, ссылку можно добавить позже через `dental-bot edit`.
2. Назначить ответственного за персональные данные; где требуется — уведомить регулятора о начале обработки (например, в России оператор подаёт уведомление в Роскомнадзор).
3. Отвечать на запросы пациентов (выгрузка/удаление) в установленный законом срок — уведомления приходят в Telegram.
4. Следить, чтобы акции и цены в файле клиники были актуальными и соответствовали закону о рекламе — бот повторяет их дословно.

## Шаблоны (адаптируйте с юристом)

**Пункт для политики клиники:**

> Для записи на приём и ответов на вопросы через WhatsApp клиника использует ИИ-помощника. Переписка обрабатывается с помощью сервиса WhatsApp Business (компания Meta) и Anthropic PBC (США) — исключительно для формирования ответов, без использования для обучения моделей ИИ. Переписка хранится на серверах в [страна] не дольше [180] дней, затем удаляется. Вы можете отозвать согласие, написав «отзываю согласие», и запросить копию или удаление своих данных, написав об этом в чат.

**Текст запроса согласия** формируется автоматически из настроек клиники (`consentRequestText` в `src/privacy/consent.ts`); свой текст можно задать в `privacy.consent_text`. При изменении текста или политики увеличьте `privacy.consent_version`.
