# ИИ-администратор стоматологии для WhatsApp

Агент на Claude отвечает пациентам клиники в WhatsApp как живой администратор:

- **записывает на приём** по реальному расписанию врачей (рабочие часы, перерывы, отпуска, праздники, занятые слоты);
- **переносит, отменяет и подтверждает** записи;
- **показывает прайс-лист**, рассказывает об услугах, врачах, адресе, оплате, акциях, отвечает на частые вопросы;
- **напоминает о визите** за 24 часа и принимает подтверждение;
- **передаёт диалог живому администратору** (жалоба, сложный вопрос, срочный случай) и сообщает ему об этом в Telegram;
- работает с **несколькими клиниками** сразу: у каждой свой номер WhatsApp, прайс, врачи и свой доступ в админку;
- отвечает на языке пациента (русский, казахский, узбекский, английский…), видит фото, вежливо просит написать текстом вместо голосового.

Защита и закон (подробно — [SECURITY.md](SECURITY.md) и [COMPLIANCE.md](COMPLIANCE.md)):

- **согласие на обработку данных** до того, как сообщения попадут к ИИ; журнал согласий; честно сообщает, что это ИИ;
- **антиспам**: лимиты на номер, автоблокировка, защита от атаки множеством номеров, дневной бюджет на ИИ;
- **защита от взлома ИИ** (prompt injection): фильтр ответов ловит утечку инструкций, фишинг, чужие ссылки и телефоны;
- **шифрование** переписки и имён в базе, маскирование данных в логах, сроки хранения и автоочистка;
- **права пациента**: выгрузка и удаление данных, отзыв согласия, отписка «СТОП»;
- админка с **отдельным токеном для каждой клиники**, защитой от перебора и журналом аудита;
- **190 автотестов**, fuzz-тесты, red-team проверка живой модели, CI с настоящей установкой мастером в Docker.

Стек: Node.js 22 + TypeScript, Claude (Messages API с инструментами), официальный WhatsApp Cloud API от Meta, SQLite.

## Установка на сервер одной командой

На чистом сервере Ubuntu 22.04/24.04 или Debian 12 (от root):

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/orkenchikai-pixel/bot/main/install.sh)
```

Мастер спросит домен, ключ Claude, данные клиники и (по желанию сразу или позже) WhatsApp и Telegram. Ключи он проверяет через API, секреты и ключ шифрования генерирует сам, затем ставит Docker, запускает бота с HTTPS и показывает, что вписать в кабинет Meta. Пошаговая инструкция для новичков, включая аренду сервера и настройку Meta, — **[START.md](START.md)**.

После установки на сервере работает команда `dental-bot`:

| Команда | Что делает |
|---|---|
| `dental-bot status` | состояние бота, HTTPS, настроек и резервных копий |
| `dental-bot edit [клиника]` | правка прайса, врачей и расписания с проверкой: файл с ошибкой не применится |
| `dental-bot whatsapp`, `dental-bot telegram` | подключить WhatsApp или уведомления (с проверкой ключей) |
| `dental-bot add-clinic` | ещё одна клиника на том же сервере |
| `dental-bot update` | обновление с резервной копией и автоматическим откатом |
| `dental-bot logs`, `info`, `backup`, `check`, `restart` | журнал, адреса и данные для Meta, резервная копия, проверка, перезапуск |

Повторный запуск установщика безопасен: он обновит код и предложит изменить настройки, ключ шифрования базы не меняется никогда. Для автоматизации все ответы можно передать переменными окружения (`NONINTERACTIVE=1`, список — `dental-bot help`).

## Как это устроено

```
Пациент в WhatsApp
      │
      ▼
Meta WhatsApp Cloud API ──вебхук──► POST /webhook/whatsapp  (подпись, повторы, лимит размера)
                                          │
                                          ▼
                                 Dispatcher: очистка текста → блок-лист → антиспам →
                                 СТОП/СТАРТ → согласие на обработку данных → пауза админа →
                                 бюджет → склейка сообщений (2,5 с), один чат — по очереди
                                          │
                                          ▼
                                 DentalAgent (Claude Opus 5.5)
                                   системный промпт клиники: правила, прайс, врачи, FAQ (кэшируется)
                                   + служебный контекст: время, имя пациента, его записи
                                          │ инструменты
                     ┌────────────────────┼─────────────────────────┐
             find_available_slots   book / reschedule /      handoff_to_admin
             (расчёт свободного     cancel / confirm          (бот на паузе,
              времени)              appointment               уведомление админу)
                                          │
                                          ▼
                              SQLite (чувствительные поля зашифрованы)
                                          │
              фильтр ответа (утечки, фишинг, ссылки, телефоны)
                                          │
                     ответ пациенту ◄─────┴─────► уведомление в Telegram / вебхук CRM
```

Почему так:

- **Свободное время считает код, а не модель.** Claude вызывает `find_available_slots` и предлагает только реальные слоты; запись в базу идёт в транзакции с проверкой пересечений — двойной записи на одно время не будет.
- **Прайс и данные клиники — только из файла клиники.** Модель не выдумывает цены и услуги.
- **Медицинские ограничения.** Агент не ставит диагнозы, при признаках неотложного состояния советует звонить в скорую и зовёт администратора.

## Быстрый старт (локально, без WhatsApp)

Нужен Node.js **22.13 или новее**.

```bash
npm install
```

```bash
cp .env.example .env
```

Впишите в `.env` ключ `ANTHROPIC_API_KEY` (получить: https://platform.claude.com → API Keys).

**Вариант 1 — чат в терминале:**

```bash
npm run chat
```

Пишите как пациент: «Здравствуйте, сколько стоит чистка?», «Хочу к терапевту в среду после обеда», «Перенесите мою запись». Команды: `/appointments`, `/reset`, `/exit`. Флаг `--verbose` покажет вызовы инструментов:

```bash
npm run chat -- --verbose --name Айгерим
```

**Вариант 2 — веб-симулятор** (удобно показывать клинике): в `.env` должно быть `SIMULATOR_ENABLED=true`, затем

```bash
npm run dev
```

и откройте http://localhost:3000/simulator (если задан `SIMULATOR_KEY` — `http://localhost:3000/simulator#key=<SIMULATOR_KEY>`). Справа видно записи пациента и уведомления, которые получил бы администратор. Симулятор пишет в отдельную базу и не занимает реальное время врачей.

В демо-клинике включено явное согласие: на первое сообщение бот попросит согласие на обработку данных (кнопки «Согласен/Не согласен»), а после «Согласен» ответит на исходный вопрос. Команда `/reset` (или кнопка «Новый диалог») удаляет тестового пациента целиком.

**Проверки качества:**

```bash
npm test
```

```bash
npm run test:coverage
```

Red-team — 15 атак на живую модель (нужен ключ Claude, стоит около доллара; отчёт в `data/redteam-report.md`):

```bash
npm run redteam
```

## Настройка клиники

Каждая клиника — отдельный файл в папке `clinics/`. Пример со всеми полями — [`clinics/demo.json`](clinics/demo.json). Скопируйте его, например в `clinics/smile.json`, и замените данные. На сервере, установленном мастером, файлы клиник лежат в `clinics.local/` (обновления кода их не трогают), а правятся командой `dental-bot edit`: после сохранения файл проверяется, и бот подхватывает изменения без перезапуска.

Главное:

| Поле | Что это |
|---|---|
| `id` | короткий латинский идентификатор (`smile`) |
| `timezone` | часовой пояс клиники: `Asia/Almaty`, `Asia/Tashkent`, `Europe/Moscow`… |
| `currency` | как писать валюту: `₸`, `₽`, `сум` |
| `working_hours_text`, `address`, `phone`, `payment_methods`, `about` | то, что агент расскажет пациенту |
| `policies`, `promotions`, `faq` | правила, акции и частые вопросы — агент отвечает строго по ним |
| `holidays` | дни, когда клиника закрыта (`YYYY-MM-DD`) |
| `booking` | шаг сетки (`slot_step_min`), за сколько минут до приёма можно записаться, на сколько дней вперёд, лимит записей на номер, срок, до которого пациент сам может отменить/перенести |
| `whatsapp.phone_number_id` | Phone number ID из Meta (см. ниже) |
| `notifications.telegram_chat_ids` | куда слать уведомления администраторам |
| `reminders.template_name` | шаблон напоминания (см. ниже) |
| `assistant.name`, `assistant.extra_instructions` | имя ассистента и особые правила клиники |
| `privacy` | режим согласия (`explicit` — по умолчанию, `notice`, `off`), версия согласия, ссылка на политику, юрлицо-оператор, маркировка каждого ответа ИИ — см. [COMPLIANCE.md](COMPLIANCE.md) |
| `limits.daily_budget_usd` | дневной бюджет на ИИ для клиники (по умолчанию $15) |
| `admin.token_sha256` | хеш токена администратора этой клиники (`npm run token`) |
| `booking.max_changes_per_day` | сколько записей/отмен/переносов один номер может сделать за сутки |

**Услуги** (`services`): `price_from` — цена «от»; `price_to` — верхняя граница диапазона; `price_fixed: true` — точная цена; `price_from: 0` — бесплатно; `duration_min` — длительность приёма (по ней считаются свободные окна); `bookable: false` — напрямую не записываем, агент предложит консультацию (импланты, брекеты, коронки).

**Врачи** (`doctors`): `services` — id услуг (или `["*"]` — все); `schedule` — рабочие интервалы по дням недели, несколько интервалов в день = перерыв: `"mon": [["09:00","13:00"], ["14:00","18:00"]]`; `days_off` — отпуск и выходные; `active: false` — временно скрыть врача.

После правки файла перезапустите сервер или вызовите `POST /admin/clinics/reload`. Если в файле ошибка, сервер напишет, в каком поле.

> Совет: прайс клиники обычно присылают в Excel/PDF. Его удобно превратить в JSON с помощью Claude: «вот прайс, сделай массив services в формате clinics/demo.json».

## Подключение WhatsApp (официальный Cloud API)

1. **Meta Business аккаунт** — https://business.facebook.com. Для работы с клиниками лучше подтвердить бизнес (Business verification) — это снимает лимиты на рассылки.
2. **Приложение** — https://developers.facebook.com → My Apps → Create App → тип *Business* → добавьте продукт **WhatsApp**.
3. **Номер телефона.** В WhatsApp → API Setup добавьте номер клиники и подтвердите его по SMS/звонку. Номер, который уже используется в обычном приложении WhatsApp, нужно либо освободить, либо подключить в режиме совместной работы с приложением WhatsApp Business (coexistence), если он доступен для вашей страны.
4. **Phone number ID** (на странице API Setup) впишите в `clinics/<клиника>.json` → `whatsapp.phone_number_id`. Если бот установлен мастером, шаги 4–6 делает команда `dental-bot whatsapp`: она проверит номер, токен и App Secret через Meta и запишет их сама.
5. **Постоянный токен.** Business Settings → Users → System users → создайте системного пользователя, дайте ему доступ к приложению и WhatsApp-аккаунту, сгенерируйте токен с разрешениями `whatsapp_business_messaging` и `whatsapp_business_management` → `WHATSAPP_ACCESS_TOKEN` в `.env`.
   Если у клиник разные WhatsApp-аккаунты и токены — укажите в файле клиники `whatsapp.access_token_env: "WA_TOKEN_SMILE"` и добавьте эту переменную в `.env`.
6. **App Secret** — App settings → Basic → App Secret → `WHATSAPP_APP_SECRET`.
7. **Вебхук.** WhatsApp → Configuration → Webhook:
   - Callback URL: `https://ваш-домен/webhook/whatsapp`
   - Verify token: любая строка, та же, что в `WHATSAPP_VERIFY_TOKEN`
   - подпишитесь на поле **messages**.

   Для теста с компьютера нужен публичный HTTPS-адрес — подойдёт туннель, например `cloudflared tunnel --url http://localhost:3000`.
8. Напишите на номер клиники с телефона — агент ответит.

**Важно про правила WhatsApp.** Если пациент написал первым, 24 часа можно отвечать любыми сообщениями (такие сообщения бесплатны). Писать первым или позже 24 часов можно только **утверждёнными шаблонами** — они платные. Поэтому напоминания используют шаблон, если пациент давно не писал.

### Шаблон напоминания

WhatsApp Manager → Message templates → Create:

- категория **Utility**, название `appointment_reminder`, язык **Russian**;
- текст, например:
  `Здравствуйте, {{1}}! Напоминаем о записи в «{{5}}»: {{2}} в {{3}}, врач — {{4}}. Пожалуйста, подтвердите визит.`
- кнопки быстрого ответа: «Подтверждаю», «Перенести», «Отменить».

После одобрения впишите в файл клиники `"reminders": { "template_name": "appointment_reminder", "template_language": "ru" }`. Порядок параметров: {{1}} имя, {{2}} дата, {{3}} время, {{4}} врач, {{5}} клиника. Нажатие кнопки приходит агенту как обычное сообщение — он подтвердит, перенесёт или отменит запись.

Если шаблон не настроен, а пациент не писал больше суток, напоминание не отправляется, а администратор получает уведомление.

## Уведомления администраторам

**Telegram:** создайте бота у @BotFather → токен в `TELEGRAM_BOT_TOKEN`. Добавьте бота в рабочую группу клиники, напишите в группе любое сообщение и откройте `https://api.telegram.org/bot<ТОКЕН>/getUpdates` — там будет `chat.id` (для групп он отрицательный). Впишите его в `notifications.telegram_chat_ids`.

**CRM, n8n, Make, Bitrix24 и т.п.:** укажите `notifications.webhook_url` — на каждое событие придёт POST с JSON (`event`, `text`, `data`).

События: новая запись, перенос, отмена, подтверждение, передача диалога администратору, сообщение пациента, пока бот на паузе, запрос пациента о его данных, тревога фильтра безопасности, блокировка номера за спам, исчерпан бюджет, сообщение с задержкой доставки, ошибки, неотправленные напоминания.

### Передача администратору

Когда агент вызывает `handoff_to_admin`, бот замолкает в этом чате на `HANDOFF_HOURS` часов (12 по умолчанию), а администратор получает суть вопроса и ссылку на чат. Сообщения пациента в это время пересылаются администратору. Ответить пациенту от имени клиники можно через админ-API (ниже). Когда пауза истечёт или администратор вернёт бота, агент увидит, о чём переписывались без него.

## Админ-API

Все запросы — с заголовком `Authorization: Bearer <токен>`. Токены:

- **владелец сервиса** — `ADMIN_TOKEN` в `.env`, видит все клиники;
- **администратор клиники** — свой токен: `npm run token` выдаст токен и его SHA-256, хеш впишите в файл клиники `"admin": { "token_sha256": "…" }`, а токен передайте клинике. Такой токен видит только свою клинику.

После 10 неудачных попыток входа IP блокируется на 15 минут. Все действия с данными пациентов попадают в журнал аудита.

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/admin/clinics` | список доступных клиник |
| POST | `/admin/clinics/reload` | перечитать файлы клиник (только владелец) |
| GET | `/admin/appointments?clinic=demo&from=2026-11-23&to=2026-11-30` | записи за период |
| POST | `/admin/appointments/:id/status` | `{"status":"completed" \| "no_show" \| "cancelled" \| "confirmed"}` |
| GET | `/admin/conversations?clinic=demo&mode=human` | чаты (например, ждущие администратора) |
| GET | `/admin/conversations/:clinic/:phone` | переписка, пациент, его записи |
| POST | `/admin/conversations/:clinic/:phone/send` | `{"text":"…"}` — ответить пациенту (бот в чате встанет на паузу) |
| POST | `/admin/conversations/:clinic/:phone/pause` | `{"hours": 4}` — выключить бота в чате |
| POST | `/admin/conversations/:clinic/:phone/resume` | вернуть бота |
| GET | `/admin/patients/:clinic/:phone/export` | **права пациента:** все его данные одним JSON-файлом |
| DELETE | `/admin/patients/:clinic/:phone?confirm=<номер>` | **права пациента:** удалить данные (записи обезличиваются) |
| GET | `/admin/privacy-requests?clinic=demo&status=open` | запросы пациентов об их данных |
| GET | `/admin/blocklist?clinic=demo` | заблокированные номера |
| POST | `/admin/blocklist/:clinic/:phone` | `{"hours": 24, "reason": "…"}` — заблокировать (без `hours` — навсегда) |
| DELETE | `/admin/blocklist/:clinic/:phone` | разблокировать |
| GET | `/admin/usage?clinic=demo&from=…&to=…` | расходы на ИИ по дням — удобно для счетов клиникам |
| GET | `/admin/audit?clinic=demo` | журнал аудита |
| POST | `/admin/reminders/run` | разослать напоминания сейчас (только владелец) |
| POST | `/admin/backup` | резервная копия базы сейчас (только владелец) |

Пример:

```bash
curl -H "Authorization: Bearer $ADMIN_TOKEN" "http://localhost:3000/admin/appointments?clinic=demo"
```

## Развёртывание

Рекомендуемый вариант — VPS в стране клиник (закон о персональных данных) с Docker. Проще всего — [мастер установки](#установка-на-сервер-одной-командой). Сначала пройдите чек-лист сервера из [SECURITY.md](SECURITY.md).

Вручную:

1. Направьте домен (A-запись) на IP сервера, в `.env` укажите `DOMAIN=bot.ваш-домен.kz` и все секреты (`npm run token`).
2. Бот в контейнере работает не от root (uid 1000), поэтому папке с базой нужен этот владелец:

```bash
mkdir -p data && sudo chown 1000:1000 data
```

3. Запустите — Caddy сам получит HTTPS-сертификат, агент наружу не открыт:

```bash
docker compose up -d --build
```

4. Callback URL вебхука в Meta: `https://bot.ваш-домен.kz/webhook/whatsapp`.

В production (`NODE_ENV=production`, в docker-compose уже стоит) сервер **не запустится**, если не заданы обязательные секреты или ключ шифрования базы — так конфигурация с дырами не попадёт в работу. Клиника, у которой вместо номера стоит `REPLACE_…`, работает только в веб-симуляторе: так бота можно установить и показать клинике до того, как Meta выдаст номер. Проверить настройки без запуска: `npm run check` (на сервере — `dental-bot check`).

Резервные копии базы создаются раз в сутки в `data/backups` (последние 14). Копируйте их ещё и вне сервера.

Ограничения текущей версии: один экземпляр сервера (очередь и счётчики антиспама — в памяти процесса) и база SQLite. Этого хватает на десятки клиник; для большего масштаба — Postgres и Redis.

| `CANARY_SECRET` | — | секрет метки, по которой ловится утечка промпта |
| `ADMIN_TOKEN` | — | токен владельца сервиса (от 32 символов) |
| `TELEGRAM_BOT_TOKEN` | — | бот для уведомлений |

| `AI_MAX_CONCURRENT` | `8` | одновременных запросов к Claude |

| `TRUST_PROXY` | `false` | сервер за Caddy/Nginx (docker-compose включает сам) |
| `SIMULATOR_ENABLED` | `false` | веб-симулятор; в production работает только с ключом |

| `HANDOFF_HOURS` | `12` | пауза бота после передачи администратору |

## Стоимость

- **Claude.** Системный промпт клиники и описания инструментов кэшируются (prompt caching), поэтому основная часть каждого запроса тарифицируется по цене чтения из кэша. Расход по каждой клинике и дню считается автоматически (`GET /admin/usage`) — по нему удобно выставлять счета клиникам, а дневные бюджеты не дадут расходам выйти из-под контроля.
- **WhatsApp.** Ответы в течение 24 часов после сообщения пациента бесплатны; шаблонные сообщения (напоминания вне окна) оплачиваются по тарифам Meta для вашей страны.

## Структура проекта

```
install.sh                 установщик: скачивает код и запускает мастер
scripts/dental-bot.sh      мастер установки и команда управления dental-bot
clinics/demo.json          настройки демо-клиники (прайс, врачи, расписание, FAQ)
src/
  index.ts                 запуск сервера
  server.ts                вебхук WhatsApp, маршруты
  agent/
    agent.ts               цикл Claude с инструментами
    prompt.ts              системный промпт клиники и служебный контекст хода
    tools.ts               инструменты: слоты, запись, перенос, отмена, подтверждение, передача админу, запросы о данных
    safety.ts              канареечная метка и настройки фильтра ответов
    history.ts             хранение истории диалога
  security/                шифрование, антиспам, лимиты, очистка входа, фильтр ответов, маскирование
  privacy/                 согласие пациента, сроки хранения
  billing/usage.ts         расчёт стоимости запросов к ИИ
  scheduling/slots.ts      расчёт свободного времени
  messaging/dispatcher.ts  конвейер проверок, очередь, склейка, паузы, отправка ответов
  whatsapp/                клиент Cloud API, разбор вебхука, форматирование
  reminders/scheduler.ts   напоминания о визитах
  notify/notifier.ts       уведомления в Telegram / вебхук
  admin/routes.ts          админ-API (токены клиник, аудит, права пациента)
  ops/backup.ts            резервные копии базы
  ops/check.ts             проверка настроек без запуска (npm run check)
  simulator/               веб-симулятор чата
  cli/                     чат в терминале, генератор токенов, проверка настроек, вызов админ-API из контейнера
scripts/redteam.ts         атаки на живую модель с автопроверками
test/                      190 тестов (vitest, fast-check), включая прогон мастера установки
START.md                   пошаговый запуск на сервере для новичков
SECURITY.md                модель угроз, чек-лист сервера, инциденты
COMPLIANCE.md              персональные данные и закон: что делает система и что нужно сделать вам
```
